# pg_stat_statement_context v1.0.0

First release. `pg_stat_statement_context` attributes query execution
statistics to the application context carried in SQL comments (SQLCommenter,
marginalia, Rails `query_log_tags`), in `application_name`, or in a
`SET LOCAL ... tags_override`. It is a companion to `pg_stat_statements`: it
keeps `calls` and `total_exec_time` per (user, database, `queryid`,
`toplevel`, tag set) in rolling time buckets, and you join to
`pg_stat_statements` on (`userid`, `dbid`, `queryid`, `toplevel`) for
everything else.

- PostgreSQL 14, 15, 16, 17 and 18, one source tree.
- SQL extension version `1.0`. `sql/pg_stat_statement_context--1.0.sql` is
  frozen; later SQL changes ship as upgrade scripts.
- Install: `make && make install`, add the library to
  `shared_preload_libraries` after `pg_stat_statements`, restart, then
  `CREATE EXTENSION pg_stat_statement_context;` (see the README).

## What's new

Everything; see [CHANGELOG.md](../../CHANGELOG.md#100---2026-10-06) for the
full list. Highlights:

- **Tag sources:** `sqlcommenter`, `marginalia` and `regex` extractors on
  comments, the `appname` extractor on `application_name`, and the
  `tags_override` GUC for sessions and transactions. All configured with GUCs
  and reloadable with `ALTER SYSTEM` + `pg_reload_conf()`.
- **Tag pipeline:** allowlist/denylist, value normalization rules, size
  limits, and per-key cardinality caps (overflow values become JSON `null`),
  counted per (role, database) by default (`cardinality_cap_scope`).
- **Rolling time buckets** (default 12 × 5 min) in a fixed-size
  shared-memory store, with eviction that reclaims expired entries first,
  and an optional **reclaim worker** (`reclaim_worker`, default `off`) that
  frees expired entries on idle systems.
- **Statistics survive clean restarts** (`save`, default `on`, like
  `pg_stat_statements.save`); a crash, an immediate shutdown, or a changed
  `bucket_interval`/`bucket_count` or version starts empty.
- **Exemplars** (`exemplar_keys`, default off; `exemplar_memory`, default
  2MB): the latest value of a high-cardinality key such as `traceparent`,
  per entry, in the `exemplars` column, without grouping by it. Over-long
  values are dropped and counted in `_info().exemplar_values_dropped`.
- **SQL surface:** the `pg_stat_statement_context`, `_totals`,
  `_last_bucket` and `_activity` views, `_info()`, `_reset()` and the
  `_extract()` debug function. Exporter-friendly: monotonic `calls_total` /
  `exec_time_total`, bucket metadata, and a last-closed-bucket view.
- **Integrations:** postgres_exporter, sql_exporter and OpenTelemetry
  Collector recipes and a Grafana dashboard (`docs/integrations/`).

## Defaults worth knowing

- `untagged = skip`: statements without tags are not recorded, so untagged
  traffic doesn't consume entries. Set `untagged = record` to keep them with
  `tags = {}`.
- `tags = 'action, controller, job'` is an allowlist: other keys are dropped
  unless you add them (or use `'*'`).
- `exclude_tags = 'traceparent, tracestate, request_id'`.
- `cardinality_cap_scope = role`: caps (off by default) count each (role,
  database) separately, so one role can't fill another's caps or probe
  which values it sent. `database` and `server` share caps between roles
  and reintroduce both; scoped caps also fill `cardinality_cap_slots`
  faster, so many-tenant servers may need more slots.

## Design questions settled for v1

The seven open questions in DESIGN.md §11 were resolved on 2026-10-05:

1. Untagged statements are skipped by default (`untagged = skip`).
2. `tags` is `jsonb`, not fixed columns.
3. The extractor DSL lives in GUCs only; no separate config file.
4. No separate `utility_textid` column for PG 14/15 (pgss behaves the same).
5. Each entry holds a ring of per-bucket counters (no bucket ID in the key).
6. Per-tag-set error and cancellation counts are out of scope.
7. A wrong `shared_preload_libraries` order is a `WARNING` only.

## Performance

Measured with pgbench against `pg_stat_statements` alone on a laptop Docker
VM ([docs/benchmarks.md](../benchmarks.md)): steady-state overhead is within
the noise of that setup (at most about 10–15% on a 0.12 ms point select, and
a dedicated run showed none); no latency spike at bucket boundaries; under
sustained high-cardinality eviction at `max_entries = 10000`, p99 is about
1.3–1.5× pgss alone on PG 18.

## Known limitations

See [docs/limitations.md](../limitations.md). In short:

- Needs `shared_preload_libraries` (a restart), so managed services can't run
  it until they allowlist it.
- Prepared statements keep the comment from PREPARE time (common drivers are
  unaffected; use `tags_override` otherwise).
- Only `calls` and `total_exec_time` are stored; failed or cancelled
  statements are not counted.
- Statistics live in shared memory: they survive clean restarts only
  (`save`), and exemplars are never saved.
- On PG 14/15, utility statements' query IDs hash their text, comments
  included, so DDL fingerprints fragment by tag set.
- Cardinality caps don't decay: an admitted value keeps its slot until
  `_reset()` or a restart.
